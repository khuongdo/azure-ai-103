=== D1 single
Q: A retail chatbot must serve 10,000 concurrent chat sessions with low latency and low cost. Answers are short FAQ-style replies, and there is no residency requirement. Which design is the best starting point?
+ A small model on a Global Standard (or Standard) pay-per-token deployment :: A smaller model reduces both latency and cost per token, and pay-per-token fits a workload that has not shown a need for reserved capacity.
- The largest available model on Provisioned capacity :: It raises cost and latency, and PTU pays off only for steady, high, proven volume.
- A reasoning model with `reasoning_effort=high` :: Hidden reasoning tokens add latency and cost to simple FAQ replies.
- A Batch deployment :: Batch has a 24-hour target and cannot serve live chat.
