Q: Your company runs an internal HR question-and-answer bot. It is used only during office hours, traffic is low, and bursts are unpredictable. There is no data residency requirement. The team wants to pay only for what it uses. Which deployment type should you choose?
+ Global Standard (pay-per-token) :: Standard deployments bill per token with no commitment, Global Standard is the documented default, and idle time costs nothing. That fits low and spiky traffic.
- Provisioned (PTU) :: Provisioned capacity is billed per PTU per hour even when idle and is sized for the peak, so most of it would be wasted on low, bursty traffic.
- Batch :: Batch is asynchronous with a 24-hour target. It cannot serve an interactive chat bot.
- Developer :: The Developer type is meant for evaluating fine-tuned models, has no SLA and a 24-hour lifetime. It is not for a production bot.

Q: An application calls a reasoning model through the Responses API with `max_output_tokens=2000`. The input is short, but responses come back with status `incomplete` and an empty `output_text`. What should you do first?
+ Raise `max_output_tokens`, because hidden reasoning tokens count toward the cap :: Reasoning tokens are billed as output and share the output budget with the visible answer. If reasoning alone uses the 2,000 tokens, no answer is produced. Learn suggests reserving a large budget first and tuning down from measured `reasoning_tokens`.
- Add "think step by step" to the prompt :: Classic chain-of-thought prompting is not recommended for reasoning models and does not free any output budget.
- Lower the temperature :: Temperature does not change how many reasoning tokens consume the output cap.
- Ask the model to print its raw reasoning so you can debug :: Extracting raw reasoning by prompting is unsupported, may violate the Acceptable Use Policy and can lead to throttling. Use the reasoning summary setting instead.

Q: A compliance team requires that a Foundry resource cannot be reached over the public internet. Applications in a virtual network and users on-premises (over VPN) must still be able to call it. Which configuration meets the requirement?
+ A private endpoint for the resource in your virtual network, with public network access set to Disabled :: A private endpoint gives the resource a private IP in your VNet, works from peered networks and from on-premises over VPN or ExpressRoute, and disabling public access removes the internet path.
- A service endpoint on the application subnet with a firewall rule :: The resource keeps its public IP and DNS still resolves to it. Service endpoints are not reachable from on-premises by default.
- An IP firewall that allows only the corporate egress addresses :: The endpoint is still publicly addressable. An allow list restricts callers, but the service is not private.
- Application Gateway with WAF in front of the resource :: A gateway adds a public front door. It does not make the resource itself private.

Q: A team wants to improve the quality of an assistant and has listed four options. According to the recommended improvement ladder, in which order should they try them?
+ Improve the prompt, ground the answers with retrieval, choose a better or larger model, then fine-tune :: Climb one rung at a time and measure after each. Fine-tuning costs training and hosting and must be redone when the base model changes, so it is the last rung.
- Fine-tune, then ground with retrieval, then improve the prompt, then change the model :: Fine-tuning first is the most expensive and least flexible option, and it cannot add private facts reliably.
- Choose a larger model, fine-tune, improve the prompt, then ground with retrieval :: A bigger model costs more per token and does not fix missing private knowledge. Cheap changes come first.
- Ground with retrieval, fine-tune, choose a larger model, then improve the prompt :: The prompt is the cheapest lever and should be tuned first. Fine-tuning comes after the model choice, not before it.

Q: A chat application receives HTTP 429 responses from a standard deployment during traffic peaks. Which TWO actions should you take?
+ Retry with exponential backoff and honor the `Retry-After` header :: 429 means TPM or RPM was exceeded. Waiting longer after each failure and respecting `Retry-After` is the documented client behavior.
+ Ramp load up gradually and give the deployment more quota :: Sharp jumps in load trigger throttling. More quota (moved from an unused deployment or by request) raises the limit itself.
- Retry immediately in a tight loop until the call succeeds :: This adds load while the limit is still exceeded, so it prolongs the throttling.
- Disable content filtering to reduce latency :: Content filtering is not the cause of 429 and removing it breaks safety requirements.
- Increase the client timeout to 29 minutes :: A longer timeout does nothing about a rate limit. Timeouts are for slow responses, not for 429.

Q: You run a safety evaluation with 300 adversarial prompts. The Violence evaluator uses the default threshold of 3, and a case passes when its score is less than or equal to the threshold. Nine outputs score 4 or higher, and three outputs score exactly 3. The release rule says the defect rate must be 2% or lower. What is the result?
+ The defect rate is 3% (9 of 300), so the release gate fails :: A defect is a score above the threshold. Scores of exactly 3 pass, so only the nine outputs at 4 or higher count: 9 / 300 = 3%.
- The defect rate is 4% (12 of 300), so the release gate fails :: This wrongly counts the three outputs with score 3. A score equal to the threshold passes.
- The defect rate is 1% (3 of 300), so the release gate passes :: This counts only the outputs at the threshold and ignores the nine that exceed it.
- A defect rate cannot be computed without human labeling :: The evaluator already returns a score per case, so the rate is computed from those scores and the threshold.

Q: A product search must find items when users type exact SKU codes such as `SKU-48213-B` and also when they describe the product in natural language. Which retrieval approach should you use in Azure AI Search?
+ Hybrid search (keyword plus vector) with the semantic ranker :: Keyword matching finds exact codes, vectors find paraphrases, Reciprocal Rank Fusion merges the lists, and the semantic ranker reorders the top results by meaning.
- Vector search only :: Embeddings treat `SKU-48213-B` and `SKU-48231-B` as almost identical, so exact codes are matched poorly.
- Keyword search only :: BM25 cannot see that "canine" and "dog" are related, so natural-language descriptions are missed.
- Exhaustive KNN with no text query :: Exhaustive KNN is an exact vector scan. It still has no keyword matching for codes.

Q: A web app creates a Sora 2 video from a prompt. The HTTP request that creates the video times out before the video is ready. How should you redesign the call?
+ Create a generation job, store the job ID, poll the job status with a delay until it succeeds, then download the file :: Video generation is an asynchronous job. The create call returns a job ID quickly and the client checks the status until it is `succeeded`, `failed` or `cancelled`.
